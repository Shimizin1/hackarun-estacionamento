## 5. Riscos

1. **Demo fora do banco novo (média)**: a coleção Postman e o roteiro consomem vagas. Rodar duas vezes seguidas no mesmo banco derruba o Newman e muda a sugestão (Verde/Azul/Roxo). Mitigação: `scripts/run_newman.py` (banco temporário) e `python scripts/reset_db.py` antes da demo ao vivo, com a API parada.
2. **`POST /admin/reset` sem autenticação (média, fora de escopo/Won't)**: qualquer pessoa que alcance a API apaga os tickets ativos e libera todas as vagas. A UI não expõe, mas a API sim (Swagger). Para a demo, não deixar a porta pública; pós-hackathon proteger ou remover.
3. **Acessibilidade não verificada com tecnologia assistiva real (média)**: NVDA, zoom 200%, Lighthouse/axe e TTS audível ficaram sem teste. Foram cobertos apenas checklist estático, contraste calculado e Chrome headless (inclui reflow a 320 px).
4. **Concorrência real (baixa)**: a reserva por `UPDATE` condicional passou em 10 threads dentro do TestClient, mas SQLite com 500 requisições simultâneas (RNF) não foi medido (Won't).
5. **Datas naive em UTC (baixa)**: a UI converte (verificado: 16:53 para 19:53 UTC), mas qualquer cliente que consuma a API direto precisa converter (BUG-03).
6. **Python 3.14 (baixa)**: os pins não instalam; README já avisa (3.11 a 3.13).
7. **Cobrança com "hora iniciada"** é decisão pendente do usuário (D2 do PO). Se mudar para fração de 15 min, `regra_arredondamento=fracao_15min` já existe e tem teste.
8. **Tempo faturável é arredondado para cima em minutos**: com 76 min exatos e latência de ms, a resposta pode trazer 62 em vez de 61 (o valor R$ 10,00 não muda). Na tabela do PO (76 min = 61) vale só para a função pura; documentar para não confundir avaliador.
